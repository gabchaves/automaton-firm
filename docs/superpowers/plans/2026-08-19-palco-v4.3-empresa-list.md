# Palco v4.3 — Empresa: back to a tidy list, more block spacing

User feedback (2026-08-19, verbatim): "pode voltar com os agentes arrumadinhos
em lista como tava aqui com os demitidos no final em empresa e separa um
pouco mais os blocos no grafo"

Reading (this is the third Empresa-crowding round; the xyflow graph has been
a recurring source of "amontoado" complaints even after two fix attempts):
the user wants the LIVE roster (Firma + Controle) presented as a plain, tidy
LIST — not xyflow graph nodes — the same orderly quality the Leaderboard tab
already has (see `packages/palco/src/leaderboard-order.ts`: live rows first
grouped by team, then ALL closed seats from both teams together at the very
end, behind a divider). Bring that exact pattern into Empresa. The "grafo"
(graph) wording in the second half of their sentence refers to whatever
visual/structural grouping remains on the page after this change — the
distinct sections (RH block, Firma list, Controle list, Encerrados list)
need clearly more spacing between them regardless of the underlying markup.

## Decision: drop xyflow/dagre for Empresa's roster entirely

This is a deliberate simplification, not a partial tweak — removing the
graph-crowding failure mode for good rather than tuning it a third time.
`@xyflow/react` and `@dagrejs/dagre` can be removed from
`packages/palco/package.json` if Empresa was their only consumer (check
first — grep the codebase for other usages before removing the deps).

## New structure for `EmpresaTab.tsx` (replaces `OrgGraph.tsx`'s canvas)

1. **RH block** — its own card at the top, unchanged in spirit: policy text,
   cycle counters (demissões/promoções/rotações), visually distinct from the
   roster below (keep whatever "unmistakable RH" styling — accent
   border/icon — the last round established, just move it out of canvas
   context into a plain `<section>`).
2. **Roster list — reuse the Leaderboard's ordering algorithm.** Import (or
   port, if leaderboard-order.ts's types don't line up 1:1 with
   `org.employees`'s shape — check `src/motor/palco-data.ts`'s
   `org.employees` fields: traderId/name/cohort/slot/status/bookMc/symbol/
   leverage/bornAt/diedAt/parentTraderId/parentName/seedNote) the SAME
   ordering contract: within each cohort, live rows first (some sensible
   order — book desc matches the Leaderboard convention, reuse it), THEN one
   shared divider, THEN every closed seat (fired before dead) from BOTH
   cohorts together at the true end of the whole roster list — not just the
   end of their own cohort's block. If `leaderboard-order.ts`'s function
   can be generalized/reused directly for this shape, prefer that over
   duplicating the ordering logic; if the shapes are too different, extract
   the SHARED status-priority/divider logic into a small helper both
   Leaderboard and Empresa import, rather than copy-pasting the algorithm.
3. **Each row**: reuse the existing `EmployeeCard`/list-item visual (avatar,
   name, mood emoji, cargo/mesa, book, status chip) that already exists from
   the prior rounds — plain vertical list, NOT a canvas, NOT absolutely
   positioned. Lineage line (`↳ mutação de X` / `↳ contratação externa` /
   seedNote fallback — the `lineageLine` logic from earlier rounds, find it,
   it may still exist in EmpresaTab.tsx or need restoring) renders as a text
   line under each row exactly like it did before the graph existed — no
   visual edges/arrows needed; the text line already carries the lineage
   information.
4. **Section headers**: "A Firma" / "Controle" as before; team-grouping
   stays for the LIVE section (two lists, or one list with clear team
   headers — your call on whichever reads cleaner, but keep the live/closed
   split as ONE unified closed-seats block at the bottom spanning both
   teams, matching the Leaderboard's pattern exactly).
5. **Encerrados** stays a distinct, clearly-separated block at the very
   bottom (already established as "own tier" from the last round — keep
   that framing, now it's just naturally a plain list too instead of an
   `.org-fallen-panel` HTML list next to a canvas).
6. **Spacing**: increase gaps between the RH block, the live roster block,
   and the Encerrados block noticeably beyond current — this directly
   addresses "separa um pouco mais os blocos". Use theme.css spacing tokens/
   patterns already established elsewhere (e.g. `.pregao-bottom-grid`'s
   `gap: 24px`, section `margin-bottom` patterns) for consistency, don't
   invent arbitrary new values.
7. **Drawer**: `EmpresaDrawer.tsx` (profile drawer on row click) is UNCHANGED
   — it already works well and isn't part of this complaint; just rewire
   whatever click handler triggered it from graph nodes to now trigger from
   plain list-item rows instead.

## Testing

Delete/replace `OrgGraph.test.tsx`'s xyflow-specific tests (zoom/bounding-box
assertions no longer apply — there's no canvas). New tests on the plain-list
version: (a) the SAME adversarial ordering regression as
`leaderboard-order.test.ts` — a fired employee with a higher book than a
live one from the OTHER cohort must still render below every live row,
proving the "true end of list" property carries over correctly; (b) a
divider renders once, only when a closed seat exists, at the boundary
between live and closed sections; (c) lineage line renders per the existing
branches (mutação/externa/seedNote-fallback/no-lineage-for-random); (d) RH
counters still render; (e) clicking a row still opens the drawer with the
right trader. Keep `EmpresaDrawer.test.tsx` as-is if it doesn't reference
graph internals.
